# Security labs, in order

Use the week prerequisites. Every lab ends with an observed result or a clearly labeled design exercise. A tabletop exercise does not count as proof that software enforces a control.

| Lab | Week | Type | Main output |
|---|---|---|---|
| [01 — HTTP](../labs/LAB-01-http.md) | 1 | Browser observation | Annotated request |
| [02 — Local web](../labs/LAB-02-local-web.md) | 1, 3 | Local page and Python | Page and ownership function |
| [03 — Threat model](../labs/LAB-03-threat-model.md) | 4 | Design | Five threat/control/test rows |
| [04 — SQL](../labs/LAB-04-sql.md) | 5 | Hosted lab + local fix | Parameterized-query assertions |
| [05 — Browser security](../labs/LAB-05-browser-security.md) | 6 | Hosted lab + local/design | XSS and CSRF comparison |
| [06 — Access control](../labs/LAB-06-access-control.md) | 7 | Hosted lab + design | Permission matrix |
| [07 — Protected notes](../labs/LAB-07-protected-notes.md) | 8–9 | Local implementation | Login and owned CRUD |
| [08 — API tests](../labs/LAB-08-api-tests.md) | 10 | Local implementation | Authorization and CSRF tests |
| [09 — Hardening](../labs/LAB-09-hardening.md) | 11 | Local review | Headers, logs and limitations |
| [10 — Transfers](../labs/LAB-10-transfers.md) | 13 | Local toy + tabletop | Invariants and concurrency design |
| [11 — Webhooks](../labs/LAB-11-webhooks.md) | 14 | Local toy + design | Event validation and deduplication |
| [12 — Incident](../labs/LAB-12-incident.md) | 15 | Tabletop | Detection and response report |

The three named hosted exercises are from [PortSwigger Web Security Academy](https://portswigger.net/web-security/learning-paths). Use your assigned instance and the platform's instructions. Read [the practice rules](../SECURITY.md) before starting.

For every report use [the lab template](../templates/LAB-REPORT.md). Include target scope, baseline, observation, cause, impact, defense, retest and limitations. Never replace “not tested” with a guessed passing result.
